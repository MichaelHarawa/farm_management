## Delivered behavior

- New `backend/apps/mobile_sync/` supplies device/session registration and audited revocation, current capabilities, frozen bootstrap/resume/pages, scoped incremental changes, typed push and owned operation-status recovery. Protocol/schema/policy/projection versions are 1. Routes use `/api/v1/mobile-sync/` with no trailing slash on individual endpoints; [the generated OpenAPI contract](../contracts/sync-api-v1.openapi.json) is executable and validated.
- Additive migrations `0001_initial` and `0002_seed_identity` introduce metadata tables/indexes/unique constraints and map existing Batch/Mortality/FeedUsage primary keys to stable UUIDs. Existing keys, amounts, dates and source timestamps remain intact. Seeded projections contain no salary, prices, owner/funding identities, nested users or credentials.
- The only enabled registry command is `poultry.mortality.record`, payload version 1. Append requires `base_version=null`, a strict UTC instant, positive integer birds and bounded nonblank evidence. Actor/age are server-derived. The existing lifecycle service now validates the original farm business date, finalized/period/lifecycle state and every dated flock/feed balance before saving; it never creates a mortality financial journal or shifts the business date.
- A canonical SHA-256 hash binds deployment, actor, original device and the complete normalized immutable command, including IDs, payload/base versions, capture time, dependencies and supersession. Accepted source effects, identity/revisions, immutable changes and permanent receipt commit together. Terminal rejections are durable; dependencies and infrastructure failures do not claim acceptance. Same-ID different content returns `idempotency_mismatch` with original-operation recovery, not a second effect. Corrections to terminal rejections require a new operation and an owned supersession link.
- The singleton stream lock precedes domain locks and is held through commit. Covered web/service/model writers publish in the same transaction. Unknown atomic/bulk writers fail closed. Unsafe generic poultry admin editors/deletes are explicitly disabled while capture is on. See [the writer matrix and runbook](../PHASE_02_RUNBOOK.md) for the precise supported boundary; privileged SQL/private ORM/imports require maintenance/reset/reseed, not a claim of automatic interception.
- Device/session/deployment claims are checked on normal REST, refresh, verify, logout and sync/replay paths. Bound mobile credentials cannot bypass the command registry through ordinary REST mutation or enter unfinished finance workflows. Normal unbound web JWT authentication remains compatible. Shared poultry roles prevent workers/stakeholders from gaining sales/cost/approval rights; worker Batch/dashboard reads use positive operational projections. Employee-profile login/link/role changes and linked-account activation are administrator-only; no real account was modified or granted access.
- Bootstrap stores immutable pages/checksums at a matching watermark. Pages are server-sized, not client-rechunked. Pull has a fixed run watermark, immutable payloads/tombstones, bounded visible rows/bytes, bounded descriptors and hidden-only scan progress. `fragments` descriptors close staged transactions even if their final page has no visible changes. Dynamic current-pack departures are evictions, not deletion; an archive pack retains the row. Mortality acknowledgements include Batch/Mortality; affected FeedUsage changes are downloaded in the same transaction's delta group.
- Guarded seed, dry-run/bounded retention and forward epoch reset commands preserve receipts and identities. Application limits: 1 MiB push/page, 50 operations, 20 dependencies, 16 KiB entity payload, 500 visible rows/descriptors, 5,000 scan rows, 10,000 changes/16 MiB group including metadata reserve; bootstrap scans <=100,000 rows, stores <=32 MiB canonical entities, expires at 24 hours and permits four unexpired snapshots/user. Database lock timeout is 5 seconds, statement timeout 20 seconds; new push commands stop starting after a 20-second request budget. These are enforced safety ceilings, not measured large-farm/public-hosting performance.
